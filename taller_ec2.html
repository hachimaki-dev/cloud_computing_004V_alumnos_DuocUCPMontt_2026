🌐 El Servidor Web (Público)

Estará en la subred pública. Le daremos una IP pública y un script de inicio (User Data) que instalará un servidor Apache automáticamente. Cualquiera en el mundo podrá ver tu sitio y servirá como base para futuros laboratorios.

⚠️ Recordatorio de Costos: Las instancias EC2 que levantemos hoy aplican para la Capa Gratuita (t2.micro), pero DEBES eliminarlas al terminar la clase para no consumir tus horas gratuitas.

Módulo 1 — Servidor Web en Subred Pública

1

Ir al panel EC2 y lanzar instancia

  • Busca EC2 en la barra superior.
  • Haz clic en Launch Instances (Lanzar instancias).
  • Nombre: Web-Publica-Taller.
  • Selecciona Amazon Linux 2023 AMI (Free tier eligible).
  • Tipo de instancia: t2.micro.
  • Key pair: Crea uno nuevo llamado llave-taller (descárgalo y guárdalo bien).
2

Configuraciones de Red (CRÍTICO)

En la sección "Network settings", haz clic en Edit.

CampoValor Correcto
VPCSelecciona tu MiVPC-Taller
SubnetSelecciona Subred-Publica
Auto-assign public IPEnable (Para poder acceder por internet)
Firewall (Security Groups)Create security group -> Nombre: SG-Web-Publica

Agrega dos reglas en el Security Group:

  • Type: SSH | Source: Anywhere (0.0.0.0/0) (O tu IP)
  • Type: HTTP | Source: Anywhere (0.0.0.0/0)
💡 ¡No la lances todavía! Nos falta el User Data en el siguiente paso.

Módulo 2 — Automatización con User Data

Para evitar tener que entrar por consola a instalar el servidor, AWS lo hará por nosotros en el arranque.

3

Pegar el Script de Inicio

Desplázate al final y abre Advanced details. Ve hasta abajo al campo User data y pega este código:

#!/bin/bash
# Actualizar el sistema
yum update -y

# Instalar servidor web Apache
yum install -y httpd

# Iniciar el servicio y habilitarlo al arranque
systemctl start httpd
systemctl enable httpd

# Crear una página HTML simple
echo "<h1>¡Hola Mundo desde mi VPC Privada!</h1><p>Este es el Servidor Web Publico.</p>" > /var/www/html/index.html

🧠 Deep Dive: ¿Por qué no usamos "sudo"?

Si alguna vez has usado Linux, sabrás que para instalar programas necesitas permisos de administrador (sudo). Sin embargo, el script de User Data se ejecuta automáticamente como el usuario "root" (el superadministrador de Linux). Por eso, los comandos funcionan directamente sin necesidad de prefijar "sudo".

  • Finalmente, haz clic en el botón naranja Launch instance.
  • Espera un minuto a que inicie. Ve a tus instancias, selecciona la Web-Publica-Taller y copia su Public IPv4 address.
  • Pégala en una nueva pestaña del navegador. ¡Deberías ver tu sitio web funcionando! 🎉

Limpieza de Recursos ⚠️

CRÍTICO: Debes eliminar las instancias EC2 ahora mismo para no incurrir en costos de AWS.
  • Ve al panel de EC2 -> Instances.
  • Selecciona Web-Publica-Taller.
  • Arriba a la derecha: Instance state -> Terminate instance.
  • Espera a que pasen a estado "Terminated".

Una vez eliminadas las instancias, puedes proceder a borrar la VPC y sus subredes como aprendimos en el taller anterior.

Evaluación de Conocimientos

1. ¿Qué ventaja principal ofrece usar "User Data" al lanzar la instancia pública?

Acelera el proceso y garantiza que el servidor se configure solo de manera estandarizada y automática sin intervención manual.
Hace que la instancia corra más rápido porque le asigna más CPU de manera oculta.

2. ¿Por qué tuvimos que habilitar la opción de "Auto-assign public IP"?

Para que AWS nos permita crear un Security Group asociado a la VPC.
Para asegurar que nuestro servidor web reciba una dirección alcanzable desde el exterior y podamos ver nuestra página web.
