T.0 ¿De qué trata este taller práctico?

💡 Guía Docente: Despliegue Real (5 min)

Objetivo: Introducir el taller como la consolidación de redes, cómputo y seguridad en un entorno Linux con AWS EC2 real.

  • Contexto: "Hoy trabajaremos sobre un servidor Ubuntu vacío en AWS Academy. Aprenderemos cómo configurarlo de forma profesional."
  • Tiempo estimado: 60 minutos.
  • Entregable: Un archivo `.txt` con los comandos de respuestas correctas que exportarán al final y subirán a AVA.

Tu misión en este taller es actuar como administrador de sistemas de un equipo de desarrollo. Configurarás una máquina vacía en la nube para que sea segura, ordenada y automatizada:

1

Aprovisionar una instancia Ubuntu EC2 en AWS Academy y guardar la llave de acceso.

2

Conectarte vía SSH usando tu terminal nativa o PuTTY de forma encriptada.

3

Crear identidades del equipo en Linux para evitar compartir el usuario administrativo.

4

Estructurar directorios del backend y proteger credenciales sensibles de bases de datos.

5

Configurar permisos Linux exactos (`chmod`/`chown`) para los archivos del proyecto.

6

Instalar y programar tareas automáticas en segundo plano con el servicio `cronie`.

⚠️ Registro de Entregable: En la pestaña Respuestas al final de este portal, deberás escribir en orden los comandos que ejecutaste para resolver el taller. Podrás descargar un reporte en `.txt` para enviárselo a tu profesor en AVA.

T.1 Módulo 0 — Crear el servidor virtual (Ubuntu EC2)

💡 Guía Docente: Aprovisionamiento en AWS (10 min)

Asegúrate de que los estudiantes elijan Ubuntu Server 22.04 LTS en la AMI y no Amazon Linux. Ubuntu requiere el usuario predeterminado ubuntu para la conexión SSH.

  • Analogía: EC2 es como arrendar un computador vacío en un centro de datos mundial.
  • Recordatorio: Descargar la llave `.pem` en formato RSA. Si se pierde no se puede volver a descargar.

Sigue estos pasos en la consola AWS para levantar tu servidor virtual:

1

Iniciar sesión e ir a EC2

Ingresa a tu entorno de AWS Academy Learner Lab, haz clic en el botón de la consola de AWS y busca EC2 en el cuadro superior de servicios.

2

Configurar Lanzamiento de Instancia

Haz clic en Launch Instance (Lanzar Instancia) y rellena los campos:

CampoValor de configuración
Name (Nombre)servidor-backend
OS Image (AMI)Ubuntu (Elige "Ubuntu Server 22.04 LTS")
Instance Typet2.micro (Incluido en la capa gratuita / lab)
Key Pair (Llave)Crear nuevo par → tipo RSA → formato .pem → Descárgalo
Network SettingsHabilita Allow SSH traffic from Anywhere (Puerto 22)
3

Esperar Estado "Running" y Anotar IP

Haz clic en Launch Instance. Espera un minuto en la lista de instancias a que el estado diga Running. Selecciona tu instancia y copia la **Dirección IPv4 Pública** (Public IP). La necesitarás a continuación.

T.2 Módulo 1 — Conectarse al servidor vía SSH

💡 Guía Docente: Explicando SSH (10 min)

SSH (Secure Shell) es el túnel seguro que encripta la comunicación entre el terminal local y el servidor remoto.

  • Detalle: Recordar que para servidores Ubuntu de AWS, el usuario de conexión inicial es ubuntu (no ec2-user ni root).
  • Recomiende la Opción A si usan macOS, Linux, o Windows con terminal moderna (PowerShell/CMD).

Elige uno de los métodos según tu sistema operativo:

Opción A: Terminal / PowerShell (Recomendado)

Navega con la terminal de tu computador al directorio donde guardaste tu llave `.pem`:

cd ~/Downloads

Conéctate al servidor usando la sintaxis SSH (reemplaza `IP_DE_TU_INSTANCIA` e ingresa `yes` si pide confirmación):

ssh -i "nombre-de-tu-llave.pem" ubuntu@IP_DE_TU_INSTANCIA

Opción B: Clientes Gráficos (PuTTY)

1. Convierte tu llave `.pem` a `.ppk` con PuTTYgen:

  • Haz clic en Load, cambia el filtro a "All Files (*.*)" y selecciona tu `.pem`.
  • Haz clic en Save private key y guárdalo en formato `.ppk`.

2. Conéctate con PuTTY:

  • Host Name: ubuntu@IP_DE_TU_INSTANCIA (puerto 22).
  • Categoría: Connection → SSH → Auth → Credentials. Carga tu `.ppk` en "Private key file".
  • Vuelve a "Session" y presiona Open.

Orientación Inicial

Una vez conectado y viendo el prompt ubuntu@ip-172-xx-xx-xx:~$, ejecuta estos comandos para familiarizarte con el entorno:

whoami
pwd
uname -a

T.3 Módulo 2 — Crear el usuario del desarrollador

💡 Guía Docente: Explicando Privilegios y Sudo (10 min)

Compartir el usuario de administrador por defecto (ubuntu) es un grave fallo de seguridad. En producción, cada miembro del equipo debe poseer una cuenta individual.

  • Concepto: sudo permite a un usuario autorizado ejecutar acciones como superusuario (root).
  • Explique a los alumnos que Linux no muestra caracteres al ingresar contraseñas por seguridad ante miradas indiscretas.

Primero, comprueba que tienes permisos de administración en este servidor remoto:

sudo whoami

Debería devolver: root

Crear el usuario de desarrollo

Crea una nueva cuenta para el desarrollador frontend/backend llamada dev_js con su carpeta personal y bash como intérprete:

sudo useradd -m -s /bin/bash dev_js

Asignar contraseña

Asigna una contraseña segura al usuario (escríbela dos veces; recuerda que no aparecerá nada en pantalla mientras escribes):

sudo passwd dev_js

Verificar su existencia

Verifica que el usuario se ha creado correctamente y que tiene su carpeta correspondiente en el sistema:

id dev_js
ls /home/

📖 Enciclopedia del Administrador: Gestión de Usuarios y Sudo

Usa esta tabla como referencia rápida para entender la administración de cuentas y delegación en sistemas GNU/Linux.

Comando Definición Ejemplo de Uso Real
sudo Superuser Do: Ejecuta un comando con los privilegios del usuario administrador (root). sudo whoami (devuelve root)
useradd User Add: Registra una nueva cuenta de usuario en el servidor. sudo useradd -m -s /bin/bash dev_js (crea home y bash)
passwd Password: Configura o actualiza la contraseña de seguridad de cualquier cuenta. sudo passwd dev_js

groups Profundizar Lista de grupos a los que pertenece el usuario activo. groups

T.4 Módulo 3 — Organizar los archivos del proyecto

💡 Guía Docente: Estructura y Touch (5 min)

Propósito: Introducir el orden de directorios estándar de un backend y el comando touch para la creación rápida de archivos vacíos.

  • Concepto: El flag -p es clave para crear directorios aninados sin que la terminal arroje errores si las carpetas padres aún no existen.

Es hora de crear la estructura base para la aplicación backend de desarrollo. Utiliza una sola línea para crear las carpetas del proyecto:

mkdir -p ~/proyecto_backend/src ~/proyecto_backend/config ~/proyecto_backend/logs

Verifica la estructura creada de manera recursiva:

ls -R ~/proyecto_backend

Crear archivos base del código y configuración

Crea un archivo vacío de inicialización Javascript (`app.js`) y un archivo de configuración para la base de datos (`db.conf`):

touch ~/proyecto_backend/src/app.js
touch ~/proyecto_backend/config/db.conf

Comprueba que los archivos existen en sus ubicaciones:

ls -l ~/proyecto_backend/src/
ls -l ~/proyecto_backend/config/

Comando Definición Ejemplo de Uso Real
mkdir Make Directory: Crea una o más carpetas vacías en la ruta seleccionada. mkdir -p ~/proyecto/src (-p crea carpetas padres)

T.5 Módulo 4 — Proteger los archivos (chmod y chown)

💡 Guía Docente: Permisos y Seguridad (15 min)

Permisos octales: 7 = rwx (Acceso total), 5 = r-x (Lectura/Entrada), 6 = rw- (Lectura/Escritura), 0 = --- (Sin acceso).

  • Importante: El archivo db.conf almacena credenciales de producción. Explicar por qué debe configurarse obligatoriamente con permisos restrictivos como 600.
  • El cambio de propietario con chown -R asigna el directorio del usuario inicial al nuevo usuario dev_js.

Actualmente el proyecto fue creado por `ubuntu` y le pertenece a él. Cambiaremos el propietario al usuario `dev_js` de forma recursiva:

sudo chown -R dev_js ~/proyecto_backend/

Asignar permisos a la carpeta principal

Configura permisos para que el propietario `dev_js` tenga acceso total (7), el grupo pueda entrar/leer (5) y el resto del mundo no tenga ningún acceso (0):

sudo chmod 750 ~/proyecto_backend/

Asegurar archivos con credenciales (`db.conf`)

Dado que `db.conf` tendrá contraseñas de bases de datos, solo el propietario `dev_js` debe poder leerlo y escribir en él (6), bloqueando a todos los demás usuarios (00):

sudo chmod 600 ~/proyecto_backend/config/db.conf

Validar la seguridad asignada

Verifica los permisos reflejados en el sistema de archivos Linux (deben verse como `drwxr-x---` para la carpeta y `-rw-------` para el archivo):

ls -l ~/ | grep proyecto_backend
ls -l ~/proyecto_backend/config/db.conf

📖 Enciclopedia del Administrador: Propietarios y Permisos (chmod/chown)

La seguridad en GNU/Linux se basa en el principio de mínimo privilegio. Usa estas reglas para restringir accesos.

Comando Definición Ejemplo de Uso Real
chown Change Owner: Modifica el propietario y el grupo dueño de un archivo o carpeta. sudo chown -R dev_js ~/proyecto/ (-R recursivo)
chmod Change Mode: Cambia los privilegios de lectura, escritura y ejecución usando octales. sudo chmod 600 ~/proyecto/config/db.conf (solo dueño lee/edita)
chmod +x Profundizar Otorga permiso de ejecución rápida a scripts de shell. chmod +x despliegue.sh (permite ejecutar como ./despliegue.sh)
chgrp Profundizar Cambia únicamente el grupo del archivo sin tocar el propietario. sudo chgrp developers db.conf

✅ Checkpoint 4 — ¿Permisos correctos?

El dueño de proyecto_backend es dev_js
Los permisos de la carpeta son drwxr-x--- (750)
Los permisos del archivo db.conf son -rw------- (600)

T.6 Módulo 5 — Instalar y activar el programador de tareas

💡 Guía Docente: Gestor de Paquetes y Demonios (10 min)

En servidores de producción, hay procesos y scripts que deben correr automáticamente a ciertas horas. Usaremos cronie, el daemon del programador de tareas de Linux.

  • Concepto: apt es la herramienta de gestión de paquetes en Ubuntu. systemctl gestiona el ciclo de vida de los servicios del sistema.
  • El parámetro --now de systemctl enable ahorra tener que ejecutar un start por separado.

Primero, actualiza el índice de repositorios local para asegurarte de descargar la versión correcta de los paquetes:

sudo apt update

Instala el programador de tareas (`cronie`) confirmando automáticamente con `-y`:

sudo apt install cronie -y

Habilita el servicio para que se inicie automáticamente en cada reinicio del servidor y arráncalo inmediatamente:

sudo systemctl enable --now crond

*Nota: En algunos entornos Ubuntu el servicio puede llamarse simplemente cron en vez de crond.

Verifica que el servicio esté en estado activo (verde) y funcionando:

sudo systemctl status crond

📖 Enciclopedia del Administrador: Paquetes y Tareas Automáticas (Apt/Systemctl)

Instalar software de forma segura y controlar su ejecución automática son tareas críticas de un DevOps.

Comando Definición Ejemplo de Uso Real
apt Advanced Package Tool: Gestor de paquetes oficial para instalar o actualizar programas en Ubuntu. sudo apt install cronie -y
systemctl System Control: Administra el arranque, apagado y estado de servicios en segundo plano. sudo systemctl enable --now crond (registra e inicia crond)
crontab Profundizar Abre el editor de tareas programadas del usuario para añadir reglas temporales. crontab -e (editar reglas) o crontab -l (listar reglas)
journalctl Profundizar Consulta la bitácora histórica de logs generados por servicios de systemd. journalctl -u crond -n 20 (muestra los últimos 20 logs de crond)

✅ Checkpoint 5 — ¿Servicio configurado?

El paquete cronie fue instalado exitosamente
El servicio crond figura en estado "active (running)"

T.7 Autoevaluación de Conceptos

💡 Guía Docente: Metacognición (5 min)

Haga que los alumnos respondan estas preguntas antes de registrar sus comandos para consolidar las justificaciones teóricas del taller.

Responde a estas preguntas rápidas para verificar tu nivel de aprendizaje:

1. ¿Por qué creamos un usuario como dev_js en lugar de trabajar siempre con ubuntu?

A) Porque el usuario ubuntu no puede ejecutar código JavaScript ni Node.
B) Por seguridad, para no compartir accesos administrativos y tener trazabilidad.
C) Porque el sistema operativo Ubuntu se ralentiza si tiene un solo usuario activo.
Correcto: Compartir credenciales administrativas aumenta los riesgos de seguridad y elimina la trazabilidad de auditorías en el sistema.

2. ¿Qué permisos otorga el comando chmod 600 db.conf?

A) Lectura y ejecución públicas, pero sin permisos de edición.
B) Lectura para todos los miembros del grupo y escritura para el dueño.
C) Lectura y escritura únicamente para el dueño, y ningún permiso para el resto.
Correcto: El valor 6 representa lectura (4) y escritura (2) para el dueño, y los ceros indican restricción total de acceso para grupo y otros.

3. ¿Qué función cumple la opción --now en el comando de servicios systemctl?

A) Activa el inicio automático y además inicia el servicio inmediatamente en este momento.
B) Detiene y desinstala el servicio inmediatamente del sistema operativo.
C) Programa la ejecución inmediata del comando una única vez en segundo plano.
Correcto: `enable --now` registra el servicio para arranques futuros y lo arranca de forma inmediata sin esperar un reinicio.
