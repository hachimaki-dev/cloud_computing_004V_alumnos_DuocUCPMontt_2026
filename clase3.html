Clase 3

EC2 y Cómputo (Servidores Virtuales)

Entiende la virtualización y el aprovisionamiento de máquinas. Usa la terminal web interactiva para "conectar" por SSH, y aprende cómo hacer público un servidor usando Ngrok o Glitch.

3.1 ¿Qué es un Servidor Virtual (EC2)?

💡 Guía Docente: El Arriendo de un Departamento (5 min)

Meta: Explicar que la nube no es magia, es alquilar computadores de alguien más de forma fraccionada.

  • Concepto 1: Virtualización. AWS compra un servidor gigante (Host) de $50,000 USD y lo divide en 100 máquinas virtuales pequeñas usando un Hypervisor.
  • Concepto 2: Elastic Compute Cloud (EC2). "Elástico" porque puedes arrendar un servidor por 5 minutos, apagarlo y dejar de pagar. En el mundo tradicional, tienes que comprar el servidor físico completo por 5 años.
  • Analogía: En lugar de construir una casa propia (servidor físico) que tarda meses y cuesta mucho dinero de golpe, EC2 es como arrendar un Airbnb por las noches que lo necesites (pago por uso).

Amazon Elastic Compute Cloud (EC2) es el servicio de cómputo principal de AWS. Te permite crear, configurar y lanzar servidores virtuales (llamados instancias) en cuestión de segundos.

En un entorno tradicional de TI (On-Premises), comprar e instalar un servidor físico puede tardar semanas o meses. Con EC2, tienes la máquina funcionando casi instantáneamente y solo pagas por los segundos o minutos que esté encendida.

Los 3 pasos para lanzar una Instancia EC2:

  • 1. Elegir la AMI (Amazon Machine Image): Es la plantilla del Sistema Operativo. ¿Quieres Windows, Ubuntu Linux, o Amazon Linux?
  • 2. Elegir el Tipo de Instancia: Es el tamaño del hardware virtual. Por ejemplo, `t2.micro` tiene 1 vCPU y 1 GB de RAM. Un `c5.18xlarge` tiene 72 vCPUs y 144 GB de RAM.
  • 3. Configurar Seguridad (Network & Security Group): ¿En qué VPC y Subred vivirá? ¿Tendrá IP pública? ¿Qué puertos abriremos en su firewall (ej. Puerto 22 para SSH, Puerto 80 para HTTP)?

3.2 Práctica: Conexión SSH a tu Instancia Linux

💡 Guía Docente: Ejecución del Simulador SSH (10 min)

Pide a un alumno voluntario que dicte los comandos o que lea la pantalla.

  • Por qué SSH: Explica que los servidores Linux en la nube no tienen "monitor ni mouse". Todo se controla mediante texto desde tu computador hacia el de AWS.
  • Instruye a los alumnos a ejecutar exactamente los siguientes comandos en el simulador:
    1. ssh ec2-user@54.120.30.5 (para entrar)
    2. sudo apt update (para buscar parches)
    3. sudo apt install apache2 (instala el servidor web HTTP)
    4. exit (para cerrar la sesión)

Imagina que acabas de lanzar una instancia Ubuntu en AWS y tiene la IP pública 54.120.30.5. Utiliza la terminal a continuación para conectarte por SSH, actualizar los paquetes e instalar un servidor web Apache.

Misiones:
1. Conéctate a la instancia usando: ssh ec2-user@54.120.30.5
2. Actualiza el sistema usando: sudo apt update
3. Instala el servidor web usando: sudo apt install apache2
4. Cierra la conexión: exit
*Tip: Escribe "help" para ver los comandos disponibles.
Bienvenido a la terminal de tu computador local. (LocalOS v1.0)
Usa comandos SSH para administrar tus servidores remotos.

3.3 Laboratorio: Desplegando a Internet (Alternativas Gratuitas)

💡 Guía Docente: De lo Local a lo Público (20 min)

AWS EC2 cuesta dinero. Para que experimenten la misma sensación de tener un servidor público, dales estas dos misiones prácticas gratuitas:

  • Opción 1 (Más técnica - Ngrok): Haz que levanten un servidor local en su terminal escribiendo python3 -m http.server 8080. Si entran a localhost:8080 lo verán. Pero si le mandan ese link a un amigo, no funciona. Luego, pídeles que instalen Ngrok y ejecuten ngrok http 8080. Ngrok les dará una URL pública real que crea un túnel hacia su máquina. ¡Su notebook es ahora una instancia EC2!
  • Opción 2 (Más rápida - Glitch): Que ingresen a Glitch.com, creen un proyecto "Hello Webpage" y vean cómo Glitch les da un servidor web y un subdominio público instantáneamente.

Tener un servidor web local es útil, pero el verdadero poder de la nube (como EC2) es tener una dirección IP pública para que clientes de todo el mundo puedan acceder a nuestra página web.

Opción 1: Túnel Ngrok

Convierte tu propio computador en un "servidor público" temporal.

  • Crea una carpeta nueva y agrega un archivo index.html.
  • Abre la terminal en esa carpeta y corre python3 -m http.server 8080.
  • Instala Ngrok (gratuito) y en otra terminal corre ngrok http 8080.
  • ¡Copia la URL https://xxxxx.ngrok-free.app y compártela!

Opción 2: Glitch.com

Un entorno de nube en el navegador. (Similar al aprovisionamiento rápido de EC2).

  • Ingresa a Glitch.com.
  • Haz clic en "New Project" y selecciona "glitch-hello-website".
  • Edita el archivo index.html en el navegador.
  • Haz clic en "Preview" -> "Open in a new window" para ver tu URL pública (ej. tu-proyecto.glitch.me).

3.4 Cierre: Metacognición y Autoevaluación

💡 Guía Docente: Preguntas del Cierre (10 min)

Evalúa el aprendizaje final sobre servidores virtuales:

  • Pregunta 1: Apunta a la diferencia de costos entre On-Premise y EC2.
  • Pregunta 2: Evalúa si entendieron que el hipervisor es la capa clave de la virtualización.

1. ¿Cuál es el principal beneficio de EC2 frente a comprar un servidor físico tradicional?

A
EC2 no requiere sistemas operativos y ejecuta código directamente en el procesador.
B
Elasticidad y pago por uso: puedes rentarlo por horas, apagarlo y dejar de pagar, evitando grandes gastos de capital.
C
Un servidor físico siempre es más barato a corto plazo que EC2.
Correcto: El modelo de nube cambia el gasto de capital (comprar hardware caro) por gasto operativo (arriendo elástico por segundo u hora).

2. En la virtualización, ¿qué componente permite que un servidor gigante de hardware hospede múltiples máquinas virtuales de clientes diferentes?

A
Internet Gateway
B
Security Group
C
El Hypervisor (Hipervisor)
Correcto: El Hipervisor es el software central en la capa de virtualización que toma los recursos físicos (CPU, RAM) y los divide lógicamente para entregárselos a cada Instancia EC2 invitada.
