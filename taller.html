T.0 ¿Qué vas a aprender en este taller?

💡 Guía Docente: Introducción al Taller (5 min)

Meta: Contextualizar que este taller es su primera experiencia real con la consola de AWS. Todo lo que hicieron en las clases anteriores con simuladores, ahora lo van a hacer de verdad.

  • Motivación: "Hoy van a crear su propio servidor en la nube. Cuando terminen, van a tener una máquina virtual funcionando en Virginia, EE.UU., a la que se conectan desde su notebook."
  • Tiempo estimado total: 90-120 minutos
  • Requisito: Cada alumno necesita acceso a una cuenta AWS (AWS Academy, Learner Lab, o cuenta personal con capa gratuita)

Al terminar este taller serás capaz de hacer todo esto por tu cuenta, sin ayuda:

1

Crear una máquina virtual (EC2) en Amazon Web Services desde la consola

2

Conectarte por SSH desde tu computador usando PuTTY y claves .pem/.ppk

3

Gestionar usuarios y contraseñas dentro de Linux (root, useradd, passwd)

4

Crear un sistema de archivos compartido en la nube con Amazon EFS

5

Montar el EFS en tu máquina virtual y verificar que funciona

6

Hacer el montaje persistente para que sobreviva reinicios del servidor (fstab)

⚠️ Importante antes de empezar: Este taller trabaja con la consola real de AWS. Cada paso que ejecutes tiene un costo potencial (aunque mínimo con la capa gratuita). Asegúrate de terminar (eliminar) tus recursos al finalizar para no generar cargos inesperados.

T.1 Conceptos Clave — No te saltes esta sección

💡 Guía Docente: Glosario Interactivo (10 min)

Pide a los alumnos que hagan clic en cada tarjeta antes de avanzar. Pregunta en voz alta: "¿Alguien puede explicar con sus palabras qué es una AMI?" para verificar comprensión.

  • Analogía clave del día: EC2 = Airbnb de computadores. En lugar de comprar casa (servidor físico), arriendas por noches (horas de uso).
  • Tiempo: 5-8 min máximo. Si dominan estos conceptos, el resto fluye solo.

Haz clic en cada tarjeta para ver la explicación. Si entiendes estos conceptos, el resto del taller fluye solo.

☁️

¿Qué es la Nube?

Clic para ver →

Es simplemente el computador de otra persona. Amazon tiene miles de computadores en sus centros de datos. Tú los "alquilas" por horas o minutos. Cuando creas una EC2, estás reservando uno de esos computadores para ti.

🖥️

EC2

Clic para ver →

Elastic Compute Cloud. Es el servicio de AWS para crear máquinas virtuales. Piénsalo como un computador sin pantalla que vive en internet. Tú te conectas a él de forma remota.

📦

Instancia

Clic para ver →

Es una máquina virtual específica que tú creaste. Como abrir una aplicación: el programa es EC2, tu instancia es tu ventana abierta.

💿

AMI

Clic para ver →

Amazon Machine Image. Es la "foto" del sistema operativo. Es como elegir si instalas Windows o Linux antes de encender el computador.

⚙️

t2.small

Clic para ver →

Es el tamaño de la máquina: cuánta RAM y CPU tiene. t2.small = 1 CPU, 2 GB RAM. Perfecta para practicar sin gastar mucho.

🔑

Par de Claves (.pem)

Clic para ver →

Como una llave y una cerradura. AWS guarda la cerradura, tú guardas la llave (archivo .pem). Sin esa llave no puedes entrar. Si la pierdes, no hay recuperación.

💾

EFS

Clic para ver →

Elastic File System. Un disco duro en la nube, separado de tu EC2. Puedes conectar el mismo EFS a varias máquinas al mismo tiempo. Como una carpeta compartida en red, pero en AWS.

🛡️

VPC y Security Group

Clic para ver →

VPC: Tu red privada en AWS. EC2 y EFS deben estar en la misma VPC para verse.

Security Group: El firewall. Define qué tráfico entra y sale. Si no abres el puerto correcto, nada funciona.

T.3 Módulo 1 — Crear y configurar una instancia EC2

💡 Guía Docente: Creación de EC2 (25 min)

Meta: Que cada alumno tenga una instancia EC2 corriendo al final de este módulo.

  • Riesgo principal: Que seleccionen la región equivocada. Asegúrate de que TODOS estén en us-east-1 antes de crear nada.
  • Tip docente: Proyecta tu pantalla y hazlo en vivo mientras ellos replican en sus cuentas.
  • Tiempo por paso: Login (2 min), Buscar EC2 (1 min), Configurar (10 min), Esperar (2 min), Anotar datos (2 min)
  • Error frecuente: Olvidar guardar el archivo .pem. Insiste 3 veces en que lo guarden.

Sigue estos pasos en orden. Cada uno construye sobre el anterior. No te saltes ninguno.

1

Ingresar a la consola de AWS

  • Ve a console.aws.amazon.com
  • Inicia sesión con tu cuenta (o la cuenta de laboratorio)
  • Verifica que la región diga US East (N. Virginia) — us-east-1
💡 ¿Por qué importa la región? AWS tiene centros de datos en todo el mundo. Todo lo que crees en una región no existe en las otras. Si creas tu EC2 en Virginia y tu EFS en Irlanda, no se pueden ver.
2

Buscar el servicio EC2

  • En la barra de búsqueda superior escribe EC2
  • Haz clic en el resultado EC2 (máquinas virtuales en la nube)
  • En el menú izquierdo, haz clic en Instancias
  • Luego en el botón naranja Lanzar instancias
3

Configurar la máquina virtual

Vas a llenar un formulario. Aquí cada campo importa:

T.4 Módulo 1B — Conectarse con PuTTY

💡 Guía Docente: Conexión PuTTY (10 min)

Este es donde más alumnos se pierden. El proceso .pem → .ppk confunde mucho.

  • Tip: Muestra el diagrama de flujo abajo y explica: "PuTTY habla un idioma (.ppk), AWS habla otro (.pem). PuTTYgen es el traductor."
  • Error frecuente: No cambian el filtro a "All Files" al cargar el .pem en PuTTYgen.
  • Error frecuente: Escriben solo la IP sin el usuario ec2-user@ delante.

PuTTY no entiende archivos .pem directamente. Necesitas convertirlo a .ppk usando PuTTYgen.

Flujo de conversión:

📄 archivo.pem Descargado de AWS
→
🔧 PuTTYgen Load → Save private key
→
🔑 archivo.ppk Formato PuTTY
→
🖥️ PuTTY ¡Conexión SSH!

Paso A: Convertir .pem → .ppk con PuTTYgen

  1. Abre PuTTYgen (viene instalado con PuTTY)
  2. Haz clic en Load
  3. ⚠️ Cambia el filtro de archivos a All Files (*.*)
  4. Navega hasta tu archivo .pem y ábrelo
  5. Verás un mensaje de éxito — haz clic en OK
  6. Haz clic en Save private key
  7. Te preguntará si quieres guardar sin frase — clic en Sí
  8. Guarda como ec2_tuNombre.ppk

Paso B: Conectarse con PuTTY

Port22

Haz clic en Open. Si aparece advertencia de seguridad, acepta. ✅ Si ves el logo de Amazon Linux con una $ al final, ¡estás dentro!

T.5 Módulo 2 — Gestión de usuarios en Linux

💡 Guía Docente: Usuarios Linux (10 min)

Concepto clave: Jerarquía de permisos. root es Dios, ec2-user es un empleado, y sudo es la autorización temporal del jefe.

  • Analogía: En una empresa, el gerente general (root) puede hacer todo. Un empleado (ec2-user) necesita pedir permiso (sudo) para acciones sensibles.
  • Nota: La contraseña 1234 es SOLO para el taller. En producción sería inaceptable.
  • Pregunta para la clase: "¿Por qué Linux no muestra los caracteres cuando escribes la contraseña?" (Seguridad: que nadie mire por encima de tu hombro)

Cuando entras por PuTTY, eres el usuario ec2-user. Tiene permisos limitados. Para cambios importantes necesitas sudo.

Jerarquía de permisos

👑 root
Administrador máximo — puede todo
↑ sudo
👤 ec2-user
Tu usuario inicial con sudo
↓ useradd
👤 ADM_PICKET
Nuevo usuario creado por ti

Paso 2.1 — Verifica quién eres

whoami

Debe decir: ec2-user

Paso 2.2 — Cambiar la contraseña de root

sudo passwd root

Escribe 1234 cuando te pida la contraseña (dos veces). Linux no muestra los caracteres — es normal.

💡 ¿Por qué sudo? Solo root puede cambiar la contraseña de root. sudo te permite ejecutar ese comando como si fueras root de forma temporal.

Paso 2.3 — Crear un nuevo usuario

sudo useradd ADM_PICKET

Verificar que se creó:

cat /etc/passwd | grep ADM_PICKET

Paso 2.4 — Asignar contraseña al nuevo usuario

sudo passwd ADM_PICKET

Escribe Duoc_2025 cuando te lo pida (dos veces).

T.6 Módulo 3 — Crear y configurar Amazon EFS

💡 Guía Docente: EFS como "Pendrive en la nube" (15 min)

Analogía: EBS es como el disco duro interno de tu laptop — solo tú lo usas. EFS es como un Google Drive compartido — varias personas pueden leer y escribir al mismo tiempo.

  • Punto crítico: La VPC del EFS DEBE coincidir con la de la EC2. Es el error #1 de este módulo.
  • Tip: Antes de que creen el EFS, haz que todos digan en voz alta su VPC ID.
  • Pregunta: "¿Qué pasa si la EC2 está en la VPC-A y el EFS en la VPC-B?" (No se ven, como dos edificios separados sin conexión)

¿Por qué EFS y no solo el disco de la EC2?

CaracterísticaEBS (disco de EC2)EFS (sistema de archivos compartido)
Conexión simultánea❌ Solo 1 instancia✅ Múltiples instancias
Persistencia⚠️ Se pierde al terminar instancia✅ Persiste independientemente
Escalabilidad❌ Tamaño fijo (ej. 8 GB)✅ Escala automáticamente
Caso de usoSistema operativo, appsLogs compartidos, archivos de config, web
1

Crear el sistema de archivos EFS

  • En la consola de AWS busca EFS
  • Haz clic en Crear sistema de archivos
  • Nombre: DiscoEFSPrueba
  • VPC: selecciona la misma VPC donde está tu EC2
  • Haz clic en Crear
2

⚠️ Verificar que la VPC coincide (CRÍTICO)

Este paso se pasa por alto frecuentemente y causa el 90% de los errores.

⚠️ Verifica en dos lugares:
1. EC2 → Instancias → tu instancia → pestaña Redes → anota VPC ID y Zona de disponibilidad
2. EFS → tu sistema de archivos → pestaña Red → verifica que VPC ID y Zona coincidan

Si las VPC no coinciden: el EFS y la EC2 no pueden verse. Es como intentar compartir una carpeta entre dos redes completamente separadas.
3

Verificar el grupo de seguridad (Puerto 2049)

El EFS usa el protocolo NFS en el puerto 2049. Tu grupo de seguridad debe permitirlo.

  • Opción A: En la configuración de red del EFS, selecciona el mismo grupo de seguridad de tu EC2
  • Opción B: Ve a EC2 → Grupos de seguridad → tu grupo → Reglas de entrada → Agrega: Tipo NFS, Puerto 2049, Origen 0.0.0.0/0

T.7 Módulo 4 — Montar el EFS en la instancia EC2

💡 Guía Docente: Montaje EFS (15 min)

Analogía: "Montar" un EFS es como enchufar un pendrive USB. La carpeta efs es el puerto USB, y el comando mount es el acto de enchufar.

  • Punto clave: Usa el diagrama de anatomía del comando para que entiendan cada parte.
  • Error frecuente: Escribir fs-XXXXXXXXX literalmente en vez de reemplazarlo con su ID real.
  • Verificación: Haz que TODOS ejecuten df -h y muestren el resultado antes de avanzar.

Paso 4.1 — Instalar amazon-efs-utils

sudo yum update -y
sudo yum install amazon-efs-utils -y
💡 ¿Qué es yum? Es el gestor de paquetes de Amazon Linux (similar a una "tienda de aplicaciones" por consola). yum install = instalar programa. -y = confirmar automáticamente.

Paso 4.2 — Obtener el ID del EFS

Ve a la consola de AWS → EFS → copia el ID del sistema de archivos: algo como fs-0a1b2c3d4e5f67890

Paso 4.3 — Crear el punto de montaje

Un "punto de montaje" es simplemente una carpeta vacía. Es como el enchufe donde conectas el disco externo.

mkdir efs

Paso 4.4 — Montar el EFS

sudo mount -t efs -o tls fs-XXXXXXXXXXXXXXXXX:/ /home/ec2-user/efs

⬆️ Reemplaza fs-XXXXXXXXXXXXXXXXX con tu ID real.

Anatomía del comando — ¿Qué significa cada parte?

sudo mount -t efs -o tls fs-XXXX:/ /home/ec2-user/efs
Permisos (sudo)
Comando
Opciones/Flags
Argumento (ID del EFS)
Ruta destino

Paso 4.5 — Verificar que el montaje funcionó

df -h

Busca una línea que termine en /home/ec2-user/efs. Verás algo como:

Resultado esperado de df -h
Filesystem Size Used Avail Use% Mounted on devtmpfs 4.0M 0 4.0M 0% /dev tmpfs 979M 0 979M 0% /dev/shm /dev/xvda1 8.0G 1.5G 6.5G 19% / fs-XXXX:/ 8.0E 0 8.0E 0% /home/ec2-user/efs
💡 ¿8.0E? Eso son 8 Exabytes. EFS no tiene límite de tamaño real — escala automáticamente. Por eso muestra ese número enorme.

Prueba escribir un archivo:

echo "Hola desde EC2" > /home/ec2-user/efs/prueba.txt
cat /home/ec2-user/efs/prueba.txt

T.8 Módulo 5 — Montaje automático (fstab)

💡 Guía Docente: Persistencia (10 min)

Analogía: Sin fstab, es como si cada vez que apagas tu laptop tuvieras que volver a instalar el pendrive. Con fstab, Linux sabe que "al encender, conecta esto automáticamente".

  • Cuidado con nano: Muchos alumnos nunca han usado un editor de texto en terminal. Muestra Ctrl+O y Ctrl+X de forma explícita.
  • Tip seguridad: Un error en fstab puede dejar el servidor sin arrancar. Por eso probamos con mount -a antes de reiniciar.

El problema: sin fstab, el EFS desaparece al reiniciar

✅ Servidor encendido EFS montado
→
🔄 sudo reboot Reinicio
→
❌ EFS desmontado ¡Hay que montarlo de nuevo!
💡 ¿Qué es /etc/fstab? Es una lista de instrucciones que Linux lee al arrancar para saber qué discos montar automáticamente. Cada línea = un disco o sistema de archivos.

Ver el contenido actual:

cat /etc/fstab

Editar fstab con nano:

sudo nano /etc/fstab

Agrega esta línea al final del archivo (sin borrar nada):

GNU nano — /etc/fstab
# /etc/fstab
# Created by anaconda on ...
UUID=xxxx-xxxx / xfs defaults,noatime 1 1
 
fs-XXXXXXXXXXXXXXXXX:/ /home/ec2-user/efs efs defaults,_netdev,tls,iam,bysystemd,automount 0 0
^O Guardar ^X Salir

⬆️ Reemplaza fs-XXXXXXXXXXXXXXXXX con tu ID real.

Anatomía de la línea de fstab:

fs-XXXX:/ /home/ec2-user/efs efs defaults,_netdev,tls,iam,bysystemd,automount 0 0
ID del EFS
Punto de montaje
Tipo
Opciones (_netdev = espera red)
dump/fsck

Probar sin reiniciar:

sudo umount /home/ec2-user/efs
sudo mount -a
df -h

mount -a monta todo lo que está en fstab. Si no hay errores y ves el EFS en df -h, la configuración está bien.

Reiniciar y verificar:

sudo reboot

PuTTY se desconectará. Espera 1-2 minutos, vuelve a conectarte, y ejecuta df -h.

✅ Si el EFS aparece montado sin que hayas hecho nada, ¡lo lograste! El montaje es persistente.

T.9 Ejercicios de práctica adicionales

💡 Guía Docente: Ejercicios (15-20 min)

Estos ejercicios son opcionales pero muy recomendados. Los de dificultad ⭐ deberían poder hacerlos todos. Los de ⭐⭐⭐ son un reto para los más avanzados.

  • Ejercicio 4 es el más valioso: demuestra el poder real del EFS (compartir archivos entre instancias).
  • Tip: Deja que intenten solos 5-10 minutos antes de dar pistas.

Intenta resolverlos sin mirar la guía primero. Haz clic en cada ejercicio para ver los detalles.

⭐

Ejercicio 1 — Repetición base

Elimina tu instancia EC2 y créala de nuevo desde cero. Repite todos los pasos del Módulo 1.

Objetivo: Que el proceso se vuelva natural. La segunda vez debería tomarte menos de 5 minutos.

⭐

Ejercicio 2 — Segundo usuario

Crea un usuario llamado OPE_TORRES con contraseña Taller_2025.

Verifica que aparezca en /etc/passwd.

sudo useradd OPE_TORRES && sudo passwd OPE_TORRES
⭐⭐

Ejercicio 3 — Permisos de carpeta en EFS

Dentro del EFS, crea una carpeta llamada compartido y dale permisos de escritura a todos los usuarios:

sudo mkdir /home/ec2-user/efs/compartido
sudo chmod 777 /home/ec2-user/efs/compartido

Investiga: ¿Qué significa 777? Cada dígito representa permisos para: dueño, grupo, y otros. 7 = leer + escribir + ejecutar.

⭐⭐⭐

Ejercicio 4 — Dos instancias, un EFS

Crea una segunda instancia EC2 en la misma VPC. Monta el mismo EFS en ella.

Crea un archivo desde la primera instancia y verifica que se ve desde la segunda. Este es el verdadero poder del EFS.

⭐⭐

Ejercicio 5 — Diagnóstico de errores

Desmonta el EFS intencionalmente:

sudo umount /home/ec2-user/efs

Luego intenta montarlo con un ID de EFS incorrecto. ¿Qué error aparece? ¿Cómo lo interpretas?
