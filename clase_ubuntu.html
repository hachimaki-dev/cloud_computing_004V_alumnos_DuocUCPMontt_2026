Introducción a Linux y Ubuntu Server

Descubre cómo piensa Linux, el puente mental entre Windows y la terminal, y practica navegando, editando archivos y administrando permisos en tiempo real.

L.1 El Puente Mental: Entendiendo Linux y Ubuntu

💡 Guía Docente: La Analogía del Automóvil (5 min)

Meta: Explicar que "Linux" no es una marca de sistema operativo cerrada, sino un motor libre.

  • El Motor (Kernel): Linux es el "motor" del auto. Es libre; cualquiera puede tomarlo y hacer modificaciones.
  • El Auto Completo (Distribución): Ubuntu es un auto terminado que usa el motor Linux, agregándole carrocería (escritorio GNOME), aire acondicionado (tienda de software) y manual de usuario.
  • El Puente con Windows: A los alumnos les asusta la terminal porque la ven como "pantalla de Matrix". Explícales que la terminal es simplemente el Explorador de Archivos de Windows, pero controlado escribiendo en vez de haciendo clics.

Muchos creen que Linux es un solo sistema operativo complejo. En realidad, Linux es solo el **Kernel** (el núcleo motor que controla el procesador, la memoria y el hardware). Ubuntu es una **Distribución** de Linux: un sistema operativo completo listo para el usuario, que empaqueta el núcleo con interfaces gráficas, herramientas y un gestor de programas.

Equivalencias Mentales: Windows vs Linux

Elemento / Paradigma Concepto en Windows Concepto en Linux (Ubuntu)
Instalar Software Descargar `.exe` de páginas web e instalar manual. Descargar de repositorios oficiales centralizados (`apt`).
Control del Sistema Explorador de Archivos y Panel de Control (Ventanas). Terminal / Consola de Comandos (Texto y automatización).
Rutas y Rutas Raíz Múltiples discos (`C:\`, `D:\`) con barras invertidas `\`. Una única raíz `/` donde todo cuelga, usando `/`.
Privilegios El usuario suele ser Administrador por defecto. Usuario sin privilegios; `sudo` para escalar cuando sea necesario.

L.2 El Árbol de Directorios: Todo es un Archivo

💡 Guía Docente: La Gran Estantería (5 min)

Meta: Explicar el sistema de archivos de Linux, donde no hay discos "C:" ni "D:", sino un solo árbol lógico.

  • La Raíz (`/`): Es el tronco del árbol. Todo nace ahí. Incluso las llaves USB y discos duros externos se montan como si fueran carpetas dentro de la raíz (en `/media` o `/mnt`).
  • Todo es un archivo: En Linux, hasta las tarjetas de red, las pantallas o los discos duros se representan como archivos en `/dev`. Si escribes texto en el archivo de un puerto, se envía por ese puerto.
  • Pide a los estudiantes que pinchen en las distintas carpetas del explorador interactivo para ver qué hace cada una.

A diferencia de Windows, donde cada disco físico tiene su letra (`C:\`, `D:\`), en Linux existe una única gran estructura jerárquica. Su origen se llama **Raíz** y se representa con una barra diagonal `/`. Todo, absolutamente todo (archivos, programas, carpetas del usuario, e incluso componentes de hardware), vive colgando de esta raíz.

📂 / (Raíz)
📂 /home (Usuarios)
📂 /etc (Configuraciones)
📂 /var (Datos Variables)
📂 /usr (Aplicaciones)
📂 /bin (Comandos Básicos)
📂 /tmp (Temporales)

/ (Raíz)

El directorio inicial del cual se desprenden todos los demás subdirectorios del sistema operativo Linux.

💡 Analogía: El hall central de un edificio. No importa a qué departamento vayas, primero debes cruzar la puerta de entrada principal.

Contenido Típico:

home/   etc/   var/   usr/   bin/   tmp/   boot/   dev/

El Árbol de Directorios: Todo es un Archivo

No hay unidades C:\ o D:\. Todo vive bajo un solo punto de partida: la Raíz (/).

/ (Raíz)
├── 📂 home/  ➜ Carpetas de usuarios (/home/usuario)
├── 📂 etc/   ➜ Archivos de configuración (¡La sala de control!)
├── 📂 var/   ➜ Logs y datos variables de aplicaciones
├── 📂 bin/   ➜ Ejecutables de comandos esenciales (ls, cd, cp)
└── 📂 tmp/   ➜ Archivos temporales (se borran al reiniciar)
Filosofía

Todo es un Archivo

En Linux, un archivo no es solo un documento. Las impresoras, los puertos de red y los discos duros se representan como archivos en el sistema.

Rutas

Separador /

Las rutas se escriben usando la barra inclinada `/` (ej: /etc/hosts) y no la barra invertida `\` típica de Windows.

Acceso

Seguridad

El usuario común solo tiene permisos totales de escritura en su carpeta personal /home/usuario.

L.3 Moverse en la Oscuridad: Navegación y Ayuda

💡 Guía Docente: Orientación Espacial (8 min)

Meta: Aprender los comandos de orientación fundamentales (`pwd`, `ls`, `cd`).

  • pwd (Print Working Directory): Equivale a mirar la barra de direcciones en el Explorador de Archivos para saber dónde estamos.
  • ls (List): Equivale a abrir la carpeta y mirar qué hay adentro.
  • cd (Change Directory): Equivale a hacer doble clic en una carpeta para meterse en ella, o usar la flecha 'atrás' (`cd ..`).
  • Misión 1: Haz que los alumnos ejecuten en la terminal los pasos indicados en la caja "Misión 1". Muéstrales cómo autocompletar con la tecla Tab (doble tabulador muestra opciones).

En la terminal no hay carpetas amarillas ni botones de navegación. Para moverte, debes guiar al sistema con comandos verbales muy cortos:

  • pwd: Te dice en qué directorio estás parado ahora mismo.
  • ls: Muestra los archivos y carpetas del directorio actual.
  • cd [ruta]: Cambia de directorio (ej: cd /etc o cd .. para subir un nivel).
  • mkdir [nombre]: Crea una carpeta nueva.
  • touch [archivo]: Crea un archivo vacío (ej: touch reporte.txt).
  • man [comando]: Muestra el manual de usuario del comando para aprender a usarlo.

L.4 Seguridad y Repositorios: Permisos, Sudo y APT

💡 Guía Docente: La Llave Maestra (8 min)

Meta: Comprender la seguridad de archivos en Linux y cómo se instala software.

  • Permisos (rwx): Explica qué significan las 3 zonas: Usuario (Propietario), Grupo y Otros.
  • sudo (SuperUser Do): Es la versión en terminal del cartel "Ejecutar como Administrador" de Windows. No uses `sudo` para todo, solo cuando requieras modificar el sistema (como en `/etc` o al instalar programas).
  • APT (Advanced Package Tool): Es como la "App Store" de Ubuntu. En lugar de ir a Google a descargar instaladores dudosos, Ubuntu le pide a sus repositorios seguros que bajen e instalen la última versión autorizada.
  • Misión 2: Ayuda a los alumnos a usar `sudo` para crear cosas en `/etc` o actualizar paquetes en la terminal simulada.

Linux fue diseñado como un sistema multiusuario sumamente seguro. Cada archivo tiene 3 tipos de permisos representados por r (read), w (write), y x (execute):

  • ls -l: Muestra los archivos en formato de lista larga, revelando permisos (ej: -rwxr-xr-x), propietarios y tamaño.
  • chmod [permisos] [archivo]: Cambia los permisos (ej: chmod +x mi_script.sh lo hace ejecutable).
  • sudo [comando]: Ejecuta un comando con permisos de administrador (Root).
  • apt update: Actualiza el índice de software disponible en los servidores oficiales (repositorios).
  • apt install [programa]: Descarga e instala un programa seguro automáticamente.

L.5 Administración de Sistemas: Procesos, Redes y Edición

💡 Guía Docente: Administrando Recursos (10 min)

Meta: Enseñar cómo inspeccionar la red, gestionar procesos colgados y editar archivos con Nano.

  • Los Procesos: En Linux los programas corren en segundo plano (servicios/daemons). `ps` y `top` nos permiten vigilarlos.
  • Nano: Es un editor súper básico por terminal. Explícales que para guardar deben presionar Ctrl+X, luego Y (o S en español) para confirmar, y luego Enter. Esto es un dolor de cabeza típico de principiante, enséñaselos con calma.
  • Misión 3: Haz que los alumnos usen `nano notas.txt` para editar un archivo, que usen `top` o `htop` para ver procesos, y que prueben su red simulada con `ping 8.8.8.8`.

Una vez dominada la terminal básica, puedes gestionar el sistema completo controlando la red, los procesos y configurando ficheros de texto plano:

  • nano [nombre_archivo]: Abre un editor de texto interactivo directo en la terminal. Muy útil para modificar configuraciones.
  • top o htop: Muestra en tiempo real el consumo de CPU y RAM de todos los procesos vivos. Presiona q para salir.
  • ip a: Muestra las direcciones IP de tus tarjetas de red físicas y virtuales.
  • ping [ip/dominio]: Comprueba si tienes conectividad de red con otro equipo (ej: ping 8.8.8.8).
  • [comando1] | grep [filtro]: El "tubo" o tubería | toma la salida del primer comando y la filtra usando grep (ej: cat notas.txt | grep Linux).

🎯 Misión 3: Procesos, Red y Nano

Ejecuta estas tareas avanzadas en el simulador:

  2. Escribe una nueva línea, y presiona Ctrl+X para guardar y salir del editor.
  3. Verifica los procesos del sistema ejecutando htop (presiona q para salir del monitor de procesos).
  4. Verifica tu IP simulada ejecutando ip a.

L.6 La Frontera del Cloud: ¿Qué es una VPC?

💡 Guía Docente: Redes en la Nube (10 min)

Meta: Explicar que para desplegar servidores en AWS necesitamos una red virtual privada (VPC).

  • La analogía: Una VPC es como un condominio privado y cerrado. Tú defines quién entra, quién sale y qué departamentos se conectan a la calle.
  • Subredes:
    • Públicas: Conectadas al Internet Gateway (el portón de salida). Tienen IPs públicas.
    • Privadas: Aisladas, ideales para bases de datos (RDS) con datos sensibles de clientes.
  • Security Groups: Son los guardias. Bloquean todos los puertos por defecto, excepto los autorizados (ej: HTTP 80 o SSH 22).

Antes de crear un servidor en AWS, debemos diseñar su red. Una VPC (Virtual Private Cloud) nos permite definir una sección aislada de la nube de AWS para lanzar recursos en una red virtual propia.

¿Qué es una VPC? (Red en AWS)

Virtual Private Cloud: Tu propia red lógica aislada en la nube de Amazon.

Subred Pública

Acceso a Internet

Tiene ruta al Internet Gateway.
Ideal para servidores web públicos (como Apache) donde entran los clientes.

Subred Privada

Aislada de Internet

Sin ruta al exterior.
Ideal para bases de datos seguras (PostgreSQL/Oracle) que nunca deben ser atacadas desde fuera.

Internet Gateway

El Enrutador

El portal/router que conecta tu VPC con internet.
Sin él, ninguna máquina de la VPC puede comunicarse con el exterior.

Seguridad Total: Los Security Groups actúan como firewalls a nivel de servidor, autorizando puertos específicos (como el 80 para HTTP o el 22 para SSH).

L.7 El Enlace Seguro: Conectarse por SSH a la Nube

💡 Guía Docente: Práctica de Conexión (10 min)

Meta: Enseñar cómo ingresar a un servidor Linux remoto en la nube de forma segura usando llaves.

  • SSH: Protocolo en el puerto 22 para administrar servidores Linux por consola.
  • La regla del 400: Explica que Linux es muy estricto con las llaves privadas (`.pem`). Si otros usuarios de tu computadora pueden leer tu llave, SSH rechazará la conexión por seguridad. Se debe arreglar ejecutando `chmod 400 llave.pem`.
  • Simulador: Desafía a los alumnos a usar la consola interactiva de abajo. Primero deben arreglar la llave y luego conectarse al servidor AWS virtual.

Para administrar tu servidor Linux hospedado en AWS u otro proveedor Cloud, usas SSH (Secure Shell). En lugar de una contraseña común, se utiliza un par de llaves criptográficas (un archivo .pem).

🔒 Regla de oro para conectar:

  1. Cambia permisos de tu archivo pem: chmod 400 llave.pem
  2. Ejecuta el comando: ssh -i llave.pem ubuntu@ip-publica-aws

SSH: Controlando Servidores Remotos

Cómo conectar tu terminal local con una máquina en la nube de AWS.

Archivo Llave (.pem)

Criptografía

Es tu llave de acceso privada. No contiene una contraseña legible, sino un conjunto de firmas criptográficas hiperseguras.

chmod 400

Permisos Estrictos

SSH exige que la llave privada sea secreta.
Si otros usuarios locales pueden leerla, SSH bloqueará la conexión. Debes protegerla con permisos read-only.

ssh -i ...

El Comando de Acceso

ssh -i llave.pem ubuntu@54.210.85.12
Le indica al cliente SSH que use la identidad (llave) para loguearse como el usuario ubuntu en la IP pública indicada.

💻 ¡Listo para administrar! Una vez dentro por SSH, la terminal que ves es la del servidor en AWS. Todo lo que escribas se ejecutará directamente allá.

L.8 Cierre: Buenas Prácticas y Autoevaluación

💡 Guía Docente: Reflexión Final (10 min)

Comenta las siguientes reglas de oro con la clase:

  • No usar sudo por flojera: Usar `sudo` todo el tiempo abre puertas traseras de seguridad y permite que cometas errores fatales de forma accidental (como borrar el disco).
  • Resolver el Quiz: Pídeles que respondan de forma individual y analiza por qué las opciones erróneas son incorrectas.

Errores Comunes del Principiante

  • "command not found": Escribiste mal el comando, o el programa no está instalado en el PATH.
  • "Permission denied": Estás tratando de modificar un archivo del sistema sin usar sudo.
  • "No such file or directory": Escribiste mal el nombre de la carpeta o archivo, o no estás parado en la ruta donde existe.

Buenas Prácticas

  • Usa la tecla Tab constantemente para autocompletar nombres y evitar errores de tipeo.
  • No uses sudo a menos que la terminal te lo pida o vayas a modificar archivos globales.
  • Antes de pegar comandos complejos de internet, leelos y usa man para saber qué hacen.
