Identidad y Accesos (IAM)

Entiende cómo la nube controla quién puede hacer qué. Aprende sobre el principio de mínimo privilegio y escribe tus primeras políticas JSON para proteger tus recursos.

5.1 El Portero de la Nube: Principio de Mínimo Privilegio

💡 Guía Docente: La Llave Maestra vs La Llave de la Habitación (5 min)

Meta: Explicar que usar el usuario "Root" es como darle la llave maestra del hotel a un huésped.

  • Identidad (Autenticación): ¿Quién eres? (Usuario y contraseña).
  • Acceso (Autorización): ¿Qué puedes hacer? (Políticas).
  • El Principio de Mínimo Privilegio: Dale a cada trabajador SÓLO los permisos estrictamente necesarios para hacer su trabajo. Si un desarrollador solo necesita leer archivos de S3, no le des acceso para borrar servidores EC2.
  • Enfatiza que en AWS todo está Denegado por defecto. Tienes que conceder permisos explícitamente usando código (JSON).

AWS Identity and Access Management (IAM) es el servicio que te permite controlar el acceso a los servicios y recursos de AWS de forma segura. IAM te permite crear Usuarios (personas) y Roles (máquinas), y asignarles Políticas.

Usuarios y Roles

Las entidades que intentan hacer cosas.

  • Usuarios IAM: Personas reales que inician sesión.
  • Roles IAM: Sombreros temporales que las máquinas (ej. un EC2) se ponen para poder hablar con otros servicios (ej. S3) sin usar contraseñas.

Políticas (Policies)

Los documentos que definen los permisos.

  • Están escritas en lenguaje JSON.
  • Por defecto todo es "Deny" (Denegado).
  • Un "Deny" explícito siempre gana sobre un "Allow".

5.3 Cierre: Metacognición y Autoevaluación

1. ¿Por qué es mala práctica utilizar el Usuario Root (el correo con el que te registraste en AWS) para tareas diarias?

A
Porque AWS cobra tarifas adicionales por iniciar sesión con Root.
B
Porque tiene acceso irrestricto y permanente a todo (incluida facturación). Si la contraseña es robada, el daño es total.
C
Porque el usuario Root no puede usar la consola web, solo la terminal.
Correcto: El usuario Root es como la llave de administrador del edificio completo. La buena práctica dicta crear un usuario IAM administrador, guardar la contraseña Root de forma segura (con MFA) y no usarlo jamás a menos que sea estrictamente necesario.

2. Un usuario tiene dos políticas JSON aplicadas a su cuenta simultáneamente. La Política A le "Permite" (Allow) acceso a S3. La Política B le "Deniega" (Deny explícito) el acceso a S3. ¿Podrá acceder a S3?

A
No. Un "Deny" explícito siempre anula cualquier "Allow".
B
Sí. Un "Allow" siempre es más fuerte porque es un permiso positivo.
C
Depende de qué política fue creada primero en el tiempo.
Correcto: La regla de evaluación de IAM es estricta: Si hay un Deny explícito en cualquier parte de la cadena, la decisión final es Denegar, sin importar cuántos Allows existan.
