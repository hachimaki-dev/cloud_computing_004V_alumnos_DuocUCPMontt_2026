Módulo 1 — Servidor Backend en Subred Privada

Ahora lanzaremos la base de datos simulada en la subred aislada.

1

Lanzar la Instancia Privada

  • Haz clic en Launch Instances nuevamente.
  • Nombre: Backend-Privado-Taller.
  • AMI: Amazon Linux 2023 / Tipo: t2.micro.
  • Key pair: Usa el mismo que creaste antes (llave-taller).
2

Red y Seguridad (DIFERENTE AL ANTERIOR)

En "Network settings" haz clic en Edit:

VPCMiVPC-Taller
SubnetSubred-Privada
Auto-assign public IPDisable (Desactivado. ¡Es privado!)
FirewallCreate security group -> Nombre: SG-Backend-Privado

En reglas de Security Group (Inbound rules):

  • Type: SSH
  • Source: Custom. En la caja de al lado, busca y selecciona el Security Group del servidor web (SG-Web-Publica).
💡 ¿Qué hicimos aquí? Le estamos diciendo a AWS: "Solo acepta conexiones SSH si vienen desde el servidor Web. Bloquea todo lo demás." Esto es seguridad a nivel de arquitectura.

Haz clic en Launch instance.

Módulo 2 — El Desafío (Evaluación Práctica) 🤔

Problema: ¡Estás fuera!

Tu servidor Backend-Privado-Taller se está ejecutando perfectamente. El problema es que NO tiene IP pública. Si intentas conectarte directamente desde tu PC de la casa o la universidad, la conexión fallará inmediatamente. Está aislado del Internet por diseño.

3

Misión de Investigación Evaluada

Tu tarea es investigar e implementar una solución para poder ingresar por consola (SSH) al Servidor Backend Privado de forma remota, manteniéndolo en la subred privada (es decir, prohibido hacer trampa dándole una IP pública o pasándolo a la subred pública).

Criterios de Evaluación:
  • Investigación (40%): ¿Qué estrategias o servicios existen en AWS para conectarse de forma segura a instancias en subredes privadas sin exponerlas directamente a internet? (Ej: A través de otras máquinas, AWS Systems Manager, Endpoints, etc.). Elige una.
  • Implementación (40%): Configura la solución que elegiste en AWS y logra conectarte a la consola del Backend-Privado-Taller. Saca una captura de pantalla donde se vea claramente tu terminal conectada al servidor, demostrando que estás dentro.
  • Reflexión (20%): ¿Por qué nos damos todo este trabajo? ¿Por qué no simplemente le damos IP pública a todas las máquinas, abrimos el puerto 22 a todo el mundo (0.0.0.0/0) y nos ahorramos el problema? Redacta un párrafo corto argumentando desde la perspectiva de ciberseguridad.

💡 Tip Inicial para tu investigación:

Piensa en la arquitectura que acabas de construir. Tienes un Servidor Web que sí tiene conexión al exterior y en el cual ya estás dentro, y ese servidor está en la misma VPC que tu base de datos privada. ¿Qué pasaría si intentas "saltar" desde adentro?

Limpieza de Recursos ⚠️

CRÍTICO: Debes eliminar las instancias EC2 ahora mismo para no incurrir en costos de AWS.
  • Ve al panel de EC2 -> Instances.
  • Selecciona Web-Publica-Taller y Backend-Privado-Taller.
  • Arriba a la derecha: Instance state -> Terminate instance.
  • Espera a que pasen a estado "Terminated".

Una vez eliminadas las instancias, puedes proceder a borrar la VPC y sus subredes como aprendimos en el taller anterior.

Evaluación de Conocimientos

1. ¿Por qué el servidor Backend necesita que el origen de su puerto 22 (SSH) sea el Security Group del Servidor Web y no "Anywhere"?

Para que solo el tráfico que ya pasó por el servidor web y fue validado pueda acceder al backend, reduciendo la superficie de ataque.
Porque AWS no permite poner "Anywhere" en subredes privadas.
